# CV Builder Interview

Build résumé/CV bullet points through a structured conversation, never by inventing or guessing content on the user's behalf. This skill has two parts: the reference material below (formatting rules, language rules, action verbs) and the interview process itself.

## The Interview Process

Ask one question at a time. For each job, project, or experience the user brings up, ask, in order:

1. **What was the actual problem or situation you were dealing with?**
2. **What did YOU specifically do — not the team, you — to address it?**
3. **What changed as a result?** Push for a number: percentage, time saved, revenue, scale, users — anything measurable. If there's no exact figure, ask for an honest estimate and flag it clearly as an estimate, never as a precise fact.
4. **What tools or technologies were involved, named specifically?**

Once all four answers exist for one experience, draft a single bullet using this formula:

**[Action verb] + [what was done] + [tool/method] + [quantified result]**

Pull the verb from the action verb bank below, matched to the right category — ask which category fits if it's ambiguous, or suggest one and let the user correct it. Never default to "responsible for," "worked on," "helped with," or other passive/vague phrasing.

Repeat for each experience the user wants to cover. At the end, list every drafted bullet together and flag any that still sound vague or unquantified so they can be fixed before anything goes on the actual CV.

**Do not fabricate.** If the user can't answer one of the four questions with something real, say so plainly and either skip the bullet or mark it as needing more information — never invent a plausible-sounding detail to fill the gap.

## Reference: Formatting Do and Don't

**Do:**
- Keep formatting consistent — spacing, bold, italics, capitalization applied the same way throughout
- List sections by importance; within each section, reverse chronological order
- Leave no unexplained date gaps
- Check that formatting survives conversion to PDF
- Use language and acronyms recognized in the specific field being targeted

**Don't:**
- Personal pronouns ("I," "we")
- Abbreviations
- Narrative style, slang, or colloquialisms
- A photo, age, or gender
- "References available upon request"
- Starting a line with a date instead of the role or organization

## Reference: Language Rules

1. **Specific, not general.** "Rebuilt the checkout flow" beats "worked on the checkout flow."
2. **Active, not passive.** "Led the migration" beats "the migration was led by."
3. **Express, not impress.** State what happened plainly; let the fact carry the weight.
4. **Fact-based — quantify and qualify.** A number, a scale, a percentage, a timeframe. An honest, clearly-flagged estimate beats no number at all.

## Reference: Top Five Mistakes

1. Spelling and grammar errors
2. Missing or wrong contact information
3. Passive language instead of action verbs
4. Poor organization — not concise, hard to skim in 15 seconds
5. Failing to state a result — describing the job instead of what changed because of it

## Reference: Résumé vs. CV

In most contexts, "CV" and "résumé" mean the same one-to-two-page document. The stricter American academic usage reserves "CV" for a longer (2+ page) document for academic/research/international-academic positions, with additional sections (publications, licenses, workshops, languages) a short résumé cuts for space. Ask which applies before assuming one-page is the target.

## Reference: Certifications and Personal Projects

**Certifications** belong on the CV only if the certifying body carries real weight in the target field and the claim would survive a follow-up question. A low-value or unrecognized certification reads as padding, not signal.

**Personal/side projects** earn a place only if they pass three checks:
- **Demonstrable** — a repo, a live link, a quantified output someone can actually inspect, not just a description
- **Relevant** — develops or proves a skill genuinely useful for the target role, not just any skill
- **Finished** — some real completed state, not abandoned halfway

A rigorous school assignment can clear this bar; a small, unfinished personal experiment often can't. The filter is what the entry demonstrates, not where it came from.

## A Note on Honesty

Describing real depth of hands-on practice is honest signal, even without "professional years" in something. Claiming to have led a specific product end-to-end, or claiming credit for a team's results without having actually led that team, is fabrication — and it's the kind of claim that collapses the moment someone asks for a name, a date, or a number. When in doubt, ask the user directly rather than assume which side of that line an answer falls on.
